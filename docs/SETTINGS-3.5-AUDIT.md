# YTArk 3.5 settings audit

Status: **generated from source for every registry control, with traced rows for the controls named in the 3.5 brief.** Generated by a one-off extraction from `TizenTube/mods/ui/settingsRegistry.js`, `config.js` and `translations/resources/en.json`. Not device-verified: every row's device behaviour is NOT RUN unless a row says otherwise.

## Method and limits

- **Controls.** Every `toggle`, `choice` and `multi` node that carries a `key` in `ui/settingsRegistry.js` (55 rows; extracted by audit_extract.py, which is heuristic, so the count is not an independent proof). Action, panel, menu and link nodes are navigation or commands, not stored controls, and are not listed.
- **Defaults.** Taken from `defaultConfig` in `config.js` (76 keys). Install-type-dependent defaults are noted in the row.
- **Write location.** Every registry control writes through `setClientSettingEndpoint`, which `resolveCommand.js` applies only when every item is a YTArk key. Keys outside the registry are listed in the second table.
- **Consumers.** Files that reference the key outside tests and generated files (a grep, not a call graph).
- **Validation evidence.** Node test files that reference the key by name. "None" means no automated test in the Node suite names it. It does not mean the behaviour is wrong.
- **Effect.** For traced rows, the effect is from the consumer code. For other rows it is the UI description text in the registry, with the consumer list as the trace. The brief asked for every row to be traced; this pass traced the controls named in the brief and the DeArrow rows. The others need a per-row trace in a later pass.
- **Activation.** Only the traced rows state timing. Device activation timing is NOT RUN for every row.

## Traced findings

1. **Startup reload is on by default.** `reloadHomeOnStartup` defaults to `true`, so each launch performs a soft reload. Its cost has not been measured. Left unchanged.
2. **Faster startup is opt-in and unmeasured.** `fasterStartup` defaults to `false`. It only shortens YTArk's readiness polling. No speedup is claimed, and no measurement exists in this repository.
3. **Misleading subtitle label corrected in English.** `enableShowOtherLanguages` adds translation targets to the auto-translate menu, not hidden caption tracks. The English label changed in 3.5. Other locales are stale until they are re-translated.
4. **Colour controls are hidden from the settings screen.** `focusContainerColor` and `routeColor` have no registry row. They are written only from the red-button panel, and the settings screen reads them back as text. The text points users at that panel.
5. **Schema 5 was undocumented.** The `config.js` header history stopped at 4. It now describes 5 and states that the release that introduced it is not recorded in this checkout.
6. **Who's Watching on exit defaults off.** With the default, the exit request is answered with `EXIT_APP`, which skips the menu. This is a behaviour change for users who expect the menu, so it is documented, not altered.
7. **DeArrow thumbnail disclosure.** `enableDeArrowThumbnails` sends the full video ID to `dearrow-thumb.ajay.app`. The title path no longer does. PRIVACY.md is corrected.
8. **SponsorBlock toggle is a single control.** An earlier extraction counted the menu resetKeys as a second row. The registry has one toggle (sponsorblock.enable); the audit now shows one row.
